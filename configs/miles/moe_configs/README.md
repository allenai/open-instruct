# Tuned SGLang fused-MoE kernel configs

`configs/triton_3_7_1/E=256,N=3072,device_name=NVIDIA_B300_SXM6_AC.json` holds the
Triton fused-MoE tiles for OLMo 3.5 Small (A4B: 256 routed experts, top-8,
`moe_intermediate_size` 3072, latent MoE dim 768) on B300 with Triton 3.7.1 and TP1.

- Generated by SGLang's MoE tuner (`benchmark/kernels/fused_moe_triton/tuning_fused_moe_triton.py`,
  288-config search space, batch sizes 1-8192) on one B300 in Beaker job `kf-hero-miles-moetune`
  (01M7CQZXJFJJANTT9ESVCVC04H, image 01M7A0QM57N9499PGFAT73SMF0). The tuner needed a local
  patch so that `Olmo3MoeForCausalLM` uses `latent_moe_dim` as the GEMM K dimension.
- This copy was rebuilt from the tuner job's per-batch-size log lines (the values SGLang
  loaded from the original file), not copied byte-for-byte. A subsequent audit fetched
  the original JSON from that experiment's result dataset and confirmed identical
  parsed contents for every batch-size entry.
- The image copies `configs/miles` to `/opt/core-rl/configs/miles`, so the Small examples set
  `SGLANG_MOE_CONFIG_DIR = "/opt/core-rl/configs/miles/moe_configs"`. The server logs
  "Using MoE kernel config from ...", then reports that the `_down` file is missing and
  reuses these tiles for the down projection.
- Measured effect: fused-MoE kernel -9% at batch 96 (565.7 -> 514.6 us), end-to-end decode
  +1.6% at R=96 and +4.4% at R=192; parity with HF unchanged. See docs/miles/olmo35-small.md.
- The directory name must match the image's Triton version (`triton_3_7_1`); rename it if the
  pinned Triton changes.
