    MILES GRPO documentation

    Use python -m open_instruct.miles for new GRPO work with supported Olmo MoE models. Open Instruct owns the researcher configuration and data/reward integration; MILES owns rollout orchestration and shared RL machinery; the adapter trains through OLMo-core and serves through SGLang. Check model and workload support below.

    The grpo.py Core/vLLM and grpo_fast.py DeepSpeed/vLLM entry points remain current alternatives for dense-model training, existing workflows and historical reproduction. See their GRPO guide for configuration and launch recipes. MILES also provides a dense Olmo 3 adapter, but that path is less extensively validated; consult model support when choosing a backend. Introducing MILES does not deprecate the existing GRPO trainers.

    Start here

    1. Start with the MILES GRPO guide for setup, the runtime image and a first run.
    2. Check support and limits, model support and topology, and read the development defaults.
    3. Copy a structured example.
    4. Read the workflow, then follow the launch guide for your host. Planning does not require GPUs or mounted checkpoints.
    5. Use operations to check completion and inspect run artifacts.

    Authority and maintenance

    Current instructions live in this directory. Example TOMLs express starting recipes. Configuration code, the pinned native parser snapshot, and runtime/miles/runtime.lock.json define accepted settings and runtime provenance.

    Maintain the generated reference with python -m scripts.miles.generate_docs and check it with python -m scripts.miles.generate_docs --check. See development for validation.

    See publication modes for current mixed-policy refresh, barrier controls and independent engine drain.
