    First-pass data for MILES mixing experiments

    This release turns the retained datasets from the early screening effort into named training inputs, so initial mixing experiments can start without repeating the preparation investigation. It provides 2,288,298 source rows across 48 named routes from 22 dataset families, including ToolRL and the supported routes of all five Nemotron blends. Qualification checks integration and representative reward behavior; downstream experiments still need to establish learning benefit.

    Start here

    The versioned release destination is:

    /weka/oe-training-default/ai2-llm/data/robertb/miles-first-pass-20261106-v2

    catalog.json is the entry point. summary.json contains per-source counts and coverage; sources/<name>/ contains prompts, verifier configuration, controls, qualification receipts, hygiene evidence and quarantine records. STAGED.json records verification on shared storage. The corrected release is offline qualified and verified on shared storage, including all 48 routes and 2,288,298 rows. The staging run passed all catalog and qualification-receipt hash checks. configs/<name>.toml provides a ready single-source [data] fragment with absolute shared paths. The versioned S3 archive below reproduces this release. It contains compressed source archives, an archive manifest and stage_release.py; the staging script verifies archive hashes, extracts the complete release and verifies the catalog's file hashes. Use s5cmd for bulk transfer; Beaker is used only for the small staging helper and CPU job.

Preserve the catalog and archive hashes; the prefix is not protected against later overwrites or deletion.

    These are explicit 16,384-token prompt variants, rendered with the bundled Olmo Pythonic tool template and tokenizer. Allow response tokens in addition to that prompt budget, for example a 32K total context with a 16K response budget. A different tokenizer/template needs preparation again; a smaller prompt limit needs an explicit smaller-context variant. long-context/ preserves longer records separately, with hashes and counts, rather than truncating histories. These 64,478 records are not qualified for this release's prompt limit.

    What qualification establishes

    Every retained row went through the training loader. Reviewed gold, wrong, near-miss, empty and truncated controls went through the training reward bridge. The 5,200 runtime control checks passed: the original 5,195 plus five controls for the recovered ToolRL row. Each receipt binds the checked prompt and verifier files to their content hashes. Code controls exercised the live service with complete test suites.

    IF uses explicit checker-family coverage: a selected real constraint is projected for each control, while training retains complete original constraint bundles. Every represented family is covered. This is not a solved witness for every combination. Other sources use their recorded reward/task strata. These checks do not independently prove every reference answer or code test correct, and no source was selected by whether a policy happened to solve it.

    ToolRL retains its historical reward scale: call targets range from -3 to 4; format-only targets from 0 to 1. NeMo tool message targets reward nonempty prose, not semantic answer quality. Tool-call rows preserve their history and declared tools, but grade the next action offline; they do not execute an environment.

    Code uses deployment version 9 at the pinned execution endpoint. Inject CODE_EXECUTION_TOKEN from Beaker secret robertb_MILES_PR2178_CODE_EXECUTION_TOKEN in workspace ai2/olmo-instruct; credentials are absent from the artifact. The endpoint is configurable through the preparation plan's code_service.api_url, recorded in each prepared verifiers.json as config.api_url. This release uses https://1n7avfskve.execute-api.us-west-2.amazonaws.com and pins the service source revision. Changing service behavior requires requalification. The service owner reports zero failures across 38,056 requests and 542,262 outcomes, tested through concurrency 128, with an AWS ceiling of 900. That is a shared service limit, not a per-run entitlement.

    Training validation

    The original v1 training smoke checks that prepared examples can be sampled, generated, graded and used in optimizer updates with the tested application image. It uses an Olmo 3.5 MoE SFT checkpoint on four B300 GPUs: two trainer ranks and two inference engines. The deterministic integration pool contains 16 rows per route (768 total), selected without policy-success filtering. It is not a substitute for the full release or a representative accuracy evaluation.

    The final audit's result dataset, 01M6SSK3PRPEPCXCH41KNJD8QV, contains noncode-audit.json and code-audit.json, including per-route consumption, reward diagnostics, checkpoint clocks and cursor hashes. Both ranks completed every expected update without skipping an optimizer step. All recorded rewards were finite; the omission metric was present and zero in every collection. The audit exposed an existing throughput-reporting bug: background collection time was compared with the driver's shorter final await. The separate reporting fix, PR #2198, was applied only to analysis, with its exact revision and file hashes recorded in the audit reports. Training used the original v1 application image identified above. The v2 fixes were checked through preparation, qualification and reward-bridge regressions; no additional GPU run is claimed.

    The smoke uses 16K response and 32K total-context limits. It retains groups with zero reward variance to exercise the training path; some code batches therefore produce zero gradients. Long code responses frequently reach the response limit. Inspect response lengths and within-group reward variance when choosing a mixing experiment's generation budget. Passing this smoke establishes integration, not learning benefit.

    The recorded sample had no positive rewards for c010 (Litmus), c044_structured, c047_structured, c046_calendar or c047_calendar. These are valid zero scores rather than service failures; offline positive controls passed. Structured/calendar parse errors describe model responses that failed the required format, and ToolRL's negative scores follow its native reward scale. Across all recorded code responses (including unused prefetch), 514 of 660 Nemotron responses reached the limit, versus 2 of 124 AceCode responses. Nemotron code may need more than 16K response tokens to avoid mostly truncated, zero-reward samples. These small-pool observations call for inspecting examples and generation budgets in the first mixing experiments, not population-level accuracy conclusions.

    Startup, compilation and checkpointing dominate these short runs. For example, the code run spent 326 seconds in inference startup and 85 seconds saving its checkpoint; its first optimizer phase took 358 seconds and its last took 37 seconds. Substantial asynchronous prefetched work remained unused at shutdown. These timings are not a sustained-throughput benchmark.

    Deliberate exclusions and follow-ups

    Area First-pass decision Follow-up
    Malformed source rows Quarantine exact IDs with reasons; retain the rest Investigate repairs separately, without changing this release
    Long histories Preserve outside the 16K-prompt variant Qualify a longer-context variant when an experiment needs it
    Math duplicate labels Quarantine two DeepMath rows labeled B versus 2 for the same numbered-choice question, and two AceReason rows whose X / \text{X} labels the existing verifier grades inconsistently Fix the existing MathVerifier normalization issue in a separate upstream change
    ReasoningGym halting Quarantine three Ultra rows: native 0.1.25 applies bool() to strings, awarding every nonempty response full credit Correct and validate the upstream scorer before admitting this family
    Judged and hybrid routes, including Nemotron Math v2 (C038), proof, GenRM, rubrics, safety and abstention Not included in this release Implement each native prompt/parsing/aggregation contract and calibrate its service; do not substitute a generic judge
    Workplace, SWE execution, Lean, browser and other interactive routes Not included; offline tool support does not claim their execution environments Integrate actual environments and recovery checks
    Alternative valid code constructions, arithmetic grammar and language detection Preserve the already documented upstream behavior Investigate deliberate grading improvements separately; do not delay initial experiments for them
    Schema combinations Native list-traversal behavior is preserved; all six structured pools were requalified after the fix. The audit records 38 rows with object branches under allOf and 16 under oneOf Investigate upstream schema satisfiability in the cleaning PR. For example, C029 direct-generation row 1378 requires a pet id through allOf while its parent forbids that undeclared key. Integration qualification does not prove every schema satisfiable.
    Sustained verifier outages Individual ungraded prompt groups are omitted and replaced; W&B reports rollout/verification/omitted_records Decide the systemic-failure stopping threshold; none is introduced here

    The first experiments should examine reward distributions, omitted-group counts, context utilization and downstream evaluations alongside learning curves. The purpose is to identify useful signal and concrete failure cases, while keeping this release and its qualification evidence reproducible.
