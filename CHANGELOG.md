- Add opt-in MILES GRPO with OLMo-core training and SGLang serving, validated structured configuration with shared constraint definitions that distinguish invalid inputs from implementation and validation gaps, consistent policy-lag aliases and early rejection of incompatible judge settings, dataset and reward integration with serialized tokenizer preservation, training samples independent of held-out counts, and contextual preparation input errors, truncation-aware group filtering, intentional prompt-exclusion table reuse, pending-prompt recovery for synchronous and asynchronous rollouts, distributed Beaker launches with distinct local service-port selection, resumable background evaluation with durable workflow and evaluation receipts, and a separate runtime pinned to the MILES source release. - Count cached SFT token statistics with Arrow batches instead of materializing a duplicate tokenized dataset (https://github.com/allenai/open-instruct/pull/1904).
- Add `--reserved_slot_tokens`, which makes a multi-token tag a single token by renaming unused `<|extra_id_N|>` vocabulary entries in place. `<think>` is `<th` `ink` `>` in the Olmo vocabularies and the BPE merges that `>` forward (`>\n`, `>\n\n` and `></` are each one token), so a generation prompt ending in `<think>` cannot produce the first token of a turn whose reasoning starts on the next line (27% of Dolci-Think traces) or whose think block is empty (every Instruct turn under the olmo35 template). Renaming a reserved slot rather than appending leaves `vocab_size` and olmo-core's `padded_vocab_size()` unchanged, so no checkpoint is resized. Both SFT paths seed each promoted row with the mean of its pieces, the olmo-core one through the vocabulary-sharded embedding DTensor that `parallelize_model` leaves behind, and only when the run is not resuming. The tokenization command that path suggests on a cache miss now carries the flag, shell-quoted, without which following the hint would rebuild the same missing cache entry forever. Refused with `--use_lora`/`--use_qlora`, whose adapter checkpoint would not carry the seeded rows. Unset by default, which keeps existing dataset cache keys (https://github.com/allenai/open-instruct/pull/1911).
- `mason.py --extra_weka_buckets` mounts additional WEKA buckets at `/weka/<bucket>`, so jobs can reach checkpoints outside `oe-adapt-default` and `oe-training-default` (e.g. `olmo-3p5-checkpoints`) (https://github.com/allenai/open-instruct/pull/1897).
- Olmo-core SFT runs write a provenance `README.md` into `output_dir` (run name, base model, Beaker/W&B pointers, launch command, optional `--sft.tracking_url`), so checkpoint directories copied around WEKA stay traceable to their run (https://github.com/allenai/open-instruct/pull/1872).
- Detect olmo-core checkpoints by config contents, and let mason pass a GCS credential to jobs (https://github.com/allenai/open-instruct/pull/1838).
- Add `over_length_strategy` to SFT tokenization, for conversations that `max_seq_length` truncation cuts short. `truncation_side` is `right`, so an over-length conversation loses its trailing EOS with the excess and becomes supervision with no terminator anywhere in it — i.e. supervision to never stop — with a trainable partial answer at the cut. Measured on the Dolci-Think 32768 cache: 2.02% of rows end on a non-EOS token and 2.00% have that final token trainable. `terminate` ends such a row with a trainable EOS, `drop` removes it, and the default `keep` preserves today's behavior so existing dataset caches stay valid (https://github.com/allenai/open-instruct/pull/1876).
- Support SFT of `allenai/Olmo-Hybrid-7B` on the olmo-core path: an `olmo3_hybrid_7B` config and HF <-> olmo-core state conversion for `model_type: olmo_hybrid`, neither of which olmo-core provides (https://github.com/allenai/open-instruct/pull/1822).
- Expose `--save_async` and `--dist_timeout_hours` for the olmo-core SFT path; both were hardcoded, and the 24h default timeout meant a mid-training stall held its GPUs invisibly (https://github.com/allenai/open-instruct/pull/1821).
- Add tool-schema support to SFT tokenization: the `tools` column is parsed (JSON strings accepted) and passed to `apply_chat_template`, assistant labels are derived from offset mappings, and the tools column is consumed rather than persisted (https://github.com/allenai/open-instruct/pull/1746).
- Drop stale async rollout results whose generating policy is more than `async_steps` behind the trainer (`max_result_age_steps`), replenishing a fresh prompt and logging a `stale_results_dropped` metric (https://github.com/allenai/open-instruct/pull/1738).
- Add `--use_cpu_adam` to GRPO to use DeepSpeed's `DeepSpeedCPUAdam` instead of `torch.optim.AdamW`. It requires a DeepSpeed stage and `--deepspeed_offload_optimizer` (the config is rejected otherwise, since `DeepSpeedCPUAdam` only steps CPU parameters), and `--deepspeed_offload_param` now requires `--deepspeed_stage 3` (https://github.com/allenai/open-instruct/pull/1654).

### Fixed
- Retry an HTTP 500 from the MILES code-execution service twice (1 s, then 2 s apart) before scoring the sample zero, and record `http_500_retries` in its diagnostics. In RL runs 4.0-4.9% of calls returned 500 and replays of those programs returned 200, so most of these zeros were service faults rather than wrong code (https://github.com/allenai/open-instruct/pull/2127).
- Fix three IFEvalG checkers that rewarded degenerate answers: `count:lowercase_counting` caps each lowercase word's frequency instead of the total, `letters:letter_counting` counts letters of every script, and `length_constraints:nth_paragraph_first_word` keeps an out-of-range paragraph index instead of redrawing it at random on every check (https://github.com/allenai/open-instruct/pull/2124).
- Reject MILES background evaluation configurations with GPQA tasks, whose `Idavidrein/gpqa` dataset is gated, without an HF_TOKEN secret reference, and document the generic SGLang profile's 64-example serial batches for long safety evaluations (https://github.com/allenai/open-instruct/pull/2111).
- Preserve sandbox shell resources in the MILES evaluator image and print a bounded olmo-eval log tail when background evaluation fails (https://github.com/allenai/open-instruct/pull/2101).
- Reject MILES background evaluation configurations that download known gated WildGuard or Gemma judges without an HF_TOKEN secret reference, and include that reference in the full-panel example (https://github.com/allenai/open-instruct/pull/2101).
- `GSM8KVerifier` compares the extracted answer and the label as exact numbers, so a correct `96.00` is no longer scored wrong against the label `96` (thousands separators are ignored on both sides; non-numeric labels keep the old string match). Rewards on existing runs can rise slightly where answers were written with trailing zeros (https://github.com/allenai/open-instruct/pull/1921).
- Register the hybrid serving backend before SGLang validates cache capabilities, keep MILES learning examples on the disabled prefix-cache default while the pinned Olmo KDA kernel lacks FP32 tracked-state snapshots, and pin the v0.1.2 async dequeue interface fixes (https://github.com/allenai/open-instruct/pull/2043).
- Fetch pinned public runtime sources for Codex reviews and remove stale private-source flags, with build tests covering both public and private dependencies (https://github.com/allenai/open-instruct/pull/2047).
- The IFEval `detectable_format:json_format` check now fails a response whose nesting exceeds the JSON decoder's recursion limit, instead of raising. A degenerate, deeply nested response (e.g. `[[[[...`) raised `RecursionError` out of `json.loads`, which the check did not catch, and the error stopped the RL run that was scoring it. Such a response now fails only this constraint; IFEval's partial credit still counts the response's other constraints. The legacy `ifeval_old` JSON checker has the same guard. Responses that parsed or failed to parse before are scored as before (https://github.com/allenai/open-instruct/pull/1979).
- `scripts/train/convert_olmo_core_to_hf.py` loads its tokenizer through `tokenizer_utils.load_tokenizer`. Under transformers 5, `AutoTokenizer.from_pretrained("allenai/dolma2-tokenizer")` returns a `GPT2Tokenizer` with a bare ByteLevel pre-tokenizer, so the export lost Dolma 2's Split regex and served a tokenization the model never trained on (https://github.com/allenai/open-instruct/pull/1937).
- Build the MILES runtime image for `linux/amd64` explicitly, so `scripts/miles/build_image.py` on an Apple-silicon Mac resolves the local amd64 base image instead of looking for an arm64 one on Docker Hub (https://github.com/allenai/open-instruct/pull/1973).
- Route the olmo-core GRPO reference-policy and post-parallelization checkpoint loads through the model-type dispatcher, so Olmo Hybrid GDN weights reach their dedicated converter instead of failing in the generic loader (https://github.com/allenai/open-instruct/pull/1844).
- SFT and DPO use explicit generation ranges for assistant labels, preserving thinker content and BOS-prefixed templates. External templates with stable turn boundaries support last-turn labeling, including Olmo 3.5-style reasoning and tool calls; closing EOS/ChatML tokens outside generation blocks are rejected. Dataset caches are invalidated for the changed labels (https://github.com/allenai/open-instruct/pull/1879).
- Zephyr's separator newline after EOS is now masked rather than trained. Empty rendered SFT rows are safely filtered, and `over_length_strategy="drop"` also detects left truncation (https://github.com/allenai/open-instruct/pull/1879).
- `mason.py` now shell-quotes every tag-like argument (`<think>`, `<|im_end|>`, `<tool name="search">`, not only ones containing `</`), so an opening tag no longer reaches the job as a redirection. Quoting moved to just before the command is joined, so the local dataset-cache run no longer tokenizes (and hashes) `</...>` args with literal quote marks (https://github.com/allenai/open-instruct/pull/1913).
- Preserve custom GPT-2 pre-tokenizers from tokenizer.json under transformers 5, including Dolma 2 tokenization, and invalidate stale dataset caches (https://github.com/allenai/open-instruct/pull/1901).
- Make the dataset cache hash independent of HF cache state and tokenizer access order: `compute_config_hash` now resolves the tokenizer before snapshotting the config, and `tokenizer_files_hash` / `dataset_commit_hash` are computed only after the tokenizer/dataset download has populated the HF hub cache, so cache jobs and training jobs agree on the numpy SFT cache dir name (https://github.com/allenai/open-instruct/pull/1802).
- `--max_train_samples` is now honored in `dpo.py`: it was declared on `DPOExperimentConfig` and hashed into the reference-logprob cache key, but only `dpo_tune_cache.py` applied it, so a subset run silently trained on the full mix (and paid the full-dataset reference pass) while looking like it had a distinct cache. Applied after the shuffle, so a subset is a random sample rather than the head of the mix; the subset is reindexed densely so the reference cache stays in bounds, and subset cache keys include the seed the subset depends on (https://github.com/allenai/open-instruct/pull/1868).
- Install `google-cloud-cli` in the Dockerfile instead of `google-cloud-sdk`: Google dropped the transitional package from its apt repo, so cold image builds fail with "Package 'google-cloud-sdk' has no installation candidate" (cached layers keep working, so this broke without any Dockerfile change) (https://github.com/allenai/open-instruct/pull/1865).
- `open_instruct/data_loader.py` no longer imports vllm at runtime (it was only used in type annotations), so entrypoints that never touch vllm -- `dpo.py` in particular -- now run on images whose torch build doesn't match vllm's ABI, and `mason.py` no longer needs `--no_auto_dataset_cache` on macOS for the vllm import (https://github.com/allenai/open-instruct/pull/1866).
- Pin `datasets>=4.8.4,<5`: datasets 4.5.0 does an unguarded `from torchvision.io import VideoReader` whenever torchvision is already imported, and torchvision 0.26 (required by torch 2.11 stacks) removed it, so every `dataset.set_format("pt")` raised ImportError -- in one case killing an 11.5h tokenization job at its final step. 4.8.4 wraps the import in try/except (https://github.com/allenai/open-instruct/pull/1867).
- `--chat_template_name` raises on an unrecognised name instead of silently using the tokenizer's own template. Use a `CHAT_TEMPLATES` key or `tokenizer_default`; unknown names include a close-match hint. `dataset_statistics.json` records the resolved source and hash. Saved checkpoints still get the dual `<|im_end|>` / `<|endoftext|>` EOS when the resolved template or `olmo_hybrid` model type needs it, not only when the flag name contains `olmo` (https://github.com/allenai/open-instruct/pull/1878).
- `--resume_from_checkpoint` is now honored in the olmo-core SFT path instead of being silently ignored, and an SFT run whose `--output_dir` already holds a checkpoint resumes from it instead of restarting (https://github.com/allenai/open-instruct/pull/1823).
- Save HF checkpoints in the weight naming their model type's released checkpoints use: `save_pretrained` applies transformers' `conversion_mapping` in reverse by default, which for `olmo_hybrid` writes norms under legacy names that vLLM (and therefore olmo-eval) refuses to load, so those model types now pass `save_original_format=False`. Verify after writing that every converted tensor reached the file, since `save_pretrained` otherwise fails silently and the checkpoint only breaks in whatever tries to load it (https://github.com/allenai/open-instruct/pull/1820).
- olmo-core SFT and DPO runs now record their Beaker experiment in the wandb config, matching `grpo_fast.py` and `dpo_tune_cache.py`, so a wandb run can be traced back to the job that produced it. The Beaker CLI lookup is performed on rank 0 only (https://github.com/allenai/open-instruct/pull/1829, fixes https://github.com/allenai/open-instruct/issues/1812).
- SFT tokenization no longer aborts on chat templates whose rendered prefixes are not literal prefixes of the full render (the olmo family swaps `<|im_end|>` for `eos_token` on the final assistant turn, which breaks whenever `eos_token` is not `<|im_end|>`). Label spans now fall back to prefix token counts, verified in three directions (span too narrow, starting inside the assistant header, or running past the turn), so a fallback can never silently mis-mask. Conversations whose spans remain underivable are masked out and dropped by `sft_tulu_filter_v1` instead of raising inside `dataset.map` and killing the whole job. Spans truncated by `max_seq_length` are exempt from the coverage check, so long conversations are kept rather than discarded (https://github.com/allenai/open-instruct/pull/1806, fixes https://github.com/allenai/open-instruct/issues/1800).
- Fix IFEvalG composition dividers and punctuation-only word counts so compliant responses receive credit; preserve the instructed spaced Markdown separator and cover composition/unique-word rewards with regressions (https://github.com/allenai/open-instruct/pull/1718).
- Add the desktop RTX 4090 to `GPU_SPECS`, so `grpo_fast.py` no longer stops at startup with `Unknown device name: NVIDIA GeForce RTX 4090`. The entry sits after `4090 laptop` because `get_device_name` returns the first key it finds in the device name (https://github.com/allenai/open-instruct/pull/2018).

### Fixed
- SFT's default checkpoint intervals collided: `olmo_core_finetune.py` forced `ephemeral_save_interval=500` through `parser.set_defaults` while `checkpointing_steps` also defaults to 500, and olmo-core requires the former to be strictly smaller, so any run that did not override one of them was rejected at startup. The forced default is now 250, and a non-positive `--ephemeral_save_interval` disables ephemeral checkpoints entirely, matching the existing `-1` convention for `max_checkpoints` (https://github.com/allenai/open-instruct/pull/1810).
- Include `--seed`, `--chat_template_name`, and `--transform_fn` in the tokenization command printed on a pre-tokenized cache miss; all three feed the cache key, so following the previous command built a cache the training job could not find (https://github.com/allenai/open-instruct/pull/1801).
- `scripts/train/convert_olmo_core_to_hf.py` now runs: it used `torch.distributed.checkpoint.state_dict.load_state_dict`, which no longer exists, and torch's generic DCP reader cannot read olmo-core's storage layout (`'_StorageInfo' object has no attribute 'transform_descriptors'`). Loads through `olmo_core.distributed.checkpoint.load_model_and_optim_state` instead (https://github.com/allenai/open-instruct/pull/1809).
- Raise a `ValueError` naming the packed instance count, global batch size, and epoch count when `olmo_core_finetune.py` computes fewer than one training step, instead of letting an undersized dataset surface as a bare `ZeroDivisionError` from olmo-core's LR scheduler (https://github.com/allenai/open-instruct/pull/1796).
- Track the CUDA 12 image suffix in the merge-queue Beaker workflow and allow enough time for the larger image build and upload (https://github.com/allenai/open-instruct/pull/1783).
- Exclude nested virtualenvs (e.g. `oe-eval-internal/.venv/`) from the Docker build context, so a uv venv inside a nested clone no longer fails the image build on a dangling host-interpreter symlink (https://github.com/allenai/open-instruct/pull/1786).
